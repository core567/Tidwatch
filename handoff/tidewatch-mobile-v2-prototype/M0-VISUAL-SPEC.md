# TideWatch Mobile V2.0 · M0 高保真视觉方案

> 交付物：`index.html`（零依赖可运行静态原型）+ 四张真实渲染截图 `shot-*.png`。
> 原型内所有数值均为**占位数据**，页面顶部有常驻标注；字段命名与真实后端契约一致
> （`taskId / status / latestReview.decision / reachId / onlineStatus / lastSeenAt / measurements`）。
> 原型不连接后端、不写库、不冒充真实监测数据。

## 0. 真实渲染验证结论

四屏已用 Edge headless 以 1:1 实际像素渲染并做像素级断言（非仅代码评审）：

| 检查项 | 结果 |
|---|---|
| 四屏均渲染深蓝渐变 Hero | ✅ 顶部采样为 #0B2A4A→#144370 渐变 |
| 四屏 TabBar 恒定吸底（屏内滚动，不被长内容顶走） | ✅ 白栏位于画板 y=830/864 边界 |
| 任务详情退回横幅红色系 | ✅ 危险浅底像素显著 |
| 现场采集「人工测量」青色图标底 | ✅ record 1444px vs detail 528px |
| 监测页迷你趋势线真实绘制（含缺测段） | ✅ 品牌蓝折线 302 像素点，缺测空洞橙色底 |
| 画板完整无横向裁切/溢出，外围深色留边 | ✅ 外缘 dark ratio 1.00 |
| 四屏内容互不相同（非同图复用） | ✅ 直方图差异 3970–5464 |

截图为程序化校验，**最终视觉观感仍需你人工打开确认**（我在此环境无法直接查看位图内容）。
打开方式：双击 `index.html`，底部 Tab 可切换；URL hash 可直达（`#s-tasks / #s-reaches / #s-detail / #s-record`）。

## 1. 设计系统（Design Tokens）

### 1.1 色彩

| 角色 | 值 | 用途 |
|---|---|---|
| navy-900 | `#071E38` | 二级页导航底、最深文字 |
| navy-800 | `#0B2A4A` | 品牌主色、渐变起点、标题、TabBar 选中 |
| navy-700/600 | `#123E68 / #1B5285` | 渐变中段/末段 |
| accent | `#1E6FE0` | 主按钮、链接、图表主线、选中描边 |
| cyan | `#18B7C8` | 科技强调（人工测量、数据点缀、渐变末端） |
| bg | `#F2F5F9` | 浅灰蓝页面底（沿用现有变量） |
| surface | `#FFFFFF` | 信息卡 |
| text / text-2 / text-3 | `#1D2B3A / #5D7186 / #8AA0B8` | 三级文字 |
| border | `#E2E8F0` | 分隔线、描边 |
| ok / watch / danger / offline | `#12A594 / #E8902A / #D84C4C / #94A3B8` | 状态四色，全部「底色 8–12% + 同色文字」双通道表达 |

**渐变**（科技感核心，克制使用）：
- Hero 头：`linear-gradient(155deg, #0B2A4A, #123E68 55%, #1B5285)`
- 主按钮/强调：`linear-gradient(135deg, #1E6FE0, #18B7C8)`
- 高优任务卡：蓝→蓝（普通高优）、`#7A4A12→#E8902A`（退回高优，警示暖色）
- 官方快照卡：`#F4FAFF→#FFFFFF` 微蓝底 + `#D9E8F8` 描边，区别于模拟数据白卡

**深浅对比**：深色 Hero 上只用白/`#CFE0F2`/`#AEC7E0` 三级文字；浅色卡内主文字 `#1D2B3A`，
禁止在白底上用 text-3 承载关键信息。状态色不仅靠颜色：徽标内必有文字（待接收/链路中断…）。

### 1.2 字体层级（rpx 换算：px×2）

| 级 | 大小 | 字重 | 用途 |
|---|---|---|---|
| H1 | 42rpx | 700 | Hero 问候/页面标题 |
| H2 | 36rpx | 700 | 详情页任务名 |
| H3 | 30rpx | 700 | 卡片分区标题（前置 8rpx 渐变竖条） |
| 数值 | 38–52rpx | 800 | 指标值（等宽感数字） |
| body | 28rpx | 400 | 卡片正文 |
| meta | 24rpx | 400 | 辅助信息 |
| caption | 20–22rpx | 400 | 来源标、时间戳、单位 |

### 1.3 间距 / 圆角 / 阴影 / 安全区

- 8pt 栅格：页边距 32rpx；卡内边距 32rpx；卡间距 28rpx；元素间 16/24rpx。
- 圆角：卡片 40rpx、控件 28rpx、小标签 20rpx、胶囊 999rpx。
- 阴影：普通卡 `0 2rpx 12rpx rgba(11,42,74,.06)`；展开卡 `0 10rpx 30rpx rgba(30,111,224,.14)` + 蓝描边；
  主按钮投影 `0 8rpx 18rpx rgba(30,111,224,.32)`；浮起 `0 8px 28px rgba(11,42,74,.12)`。
- Hero 与内容：Hero 底部 -36rpx 圆角 + 内容 `margin-top:-60rpx` 上浮，指标玻璃条压在渐变上。
- 安全区：TabBar/操作栏底部统一 `padding-bottom: calc(24rpx + env(safe-area-inset-bottom))`；
  页面滚动内容预留 192rpx 避免被固定栏遮挡。

### 1.4 组件规范（M1 落地为自定义组件）

- **page-hero**：渐变色头，插槽：标题/副标题/右侧状态胶囊/内嵌玻璃指标条。
- **glass-tile**：Hero 内玻璃拟态指标（半透明白 9% + 1px 14% 白边），数字按状态着色，可点按 `:active` 20% 白。
- **stat / metric-card**：大白数值 + 小单位 + 指标名 + 时间；三列时相邻列 1px 分隔线。
- **status-badge**：ok/watch/danger/off/accent/outline 六色，文字+底色，无单独成色。
- **chip**：灰底（普通）/ 蓝底（河段）/ 红底（事件号）/ 虚线蓝（任务要求项）。
- **section-card**：白卡 + 竖条标题 + 右侧 more 插槽。
- **source-tag**：沿用现有组件；模拟=灰描边、官方=蓝、人工=青；任何数据旁必挂。
- **timeline-view / sparkline / empty-state / error-state / list-loading**：M3/M4 实现。

### 1.5 TabBar

custom-tab-bar：白底 152rpx + 顶部分割线；SVG 线性图标（24×24，stroke 2），
未选 `#8AA0B8`，选中 `#1E6FE0` + 文字加粗；图标为自绘 SVG，无 PNG、无外部依赖。

### 1.6 三态反馈

- 加载：骨架灰块（指标卡/任务卡轮廓），不用转圈占满整页。
- 空态：插画位（emoji 过渡）+ 一句解释 + 可执行动作（切分类/下拉刷新）；筛选栏不消失。
- 错误：原因文案（RequestError 已含网络指引）+ 重试按钮；静默刷新失败保留旧数据不覆盖。

## 2. 四个核心页面布局与交互状态

### 2.1 巡检工作台 `s-tasks`（截图 `shot-s-tasks.png`）

自上而下：
1. 渐变 Hero：问候语 + 日期 +「你有 N 个待接收任务」（N 来自真实 `summarize`）；右上实时连接胶囊（绿点/橙点断线）。
2. 玻璃四桶：待接收(红)/进行中(橙)/待复核(青)/已完成(绿)，**点击即切换筛选**，与 pills 双向同步。
3. 高优先级横滑卡：仅 `priority=HIGH` 且未完成；退回高优用暖色卡区分；卡片上真实字段（河段/动作/eventId）。
4. 筛选 pills：待处理/进行中/待复核/已完成/全部，深蓝实底为选中；切换是**纯本地派生、零请求**（保留已修复的单一数据源链路）。
5. 任务卡：标题 + 状态徽标；高优卡左 8rpx 红条；meta 行（河段中文名/动作中文名/事件号红 chip）；
   底部截止时间或「↺ 复核退回：摘要 · 相对时间」+ 高优标记。
6. 快捷入口：异常事件（带活动数）、水环境监测（带最后观测时间），switchTab 真实跳转，非装饰。

交互态：pill 选中、玻璃卡按压、任务卡按压投影加深、下拉刷新（保留当前筛选、不闪全屏 loading）、
WS 推送后数字/列表同源更新。

### 2.2 水环境监测 `s-reaches`（截图 `shot-s-reaches.png`）

1. Hero 副标题直接写口径：「连续观测来自 MQTT 模拟链路（明确标注）· 官方自动站为快照数据」；右上「链路中断 3」。
2. 三断面卡 A/B/C：
   - 左侧字母方块（B 为蓝青渐变表示展开态）；断面名 + 官方候选站名（余家湖/宗关/龙王庙，**带「待核实」**）+ LOGICAL 坐标状态。
   - 右上链路胶囊：**链路中断 = 橙色 watch**（不是红色错误——它表达的是推送链路，不是水质事故）。
   - 三指标速览：水位 m / 浊度 NTU / 水流等级（真实字段 `waterLevel/turbidity/flowLevel`，来自 `/reaches/{id}/latest`），每格带「2 天前」时间。
   - 卡脚：`最后有效观测 时间 + [模拟数据]来源标`；右侧固定文案 **「离线 ≠ 现场正常，仅表示模拟链路停止推送」**。
3. B 卡展开态（详情页内容预览）：
   - 指标切换 tab（水位/浊度/水流）；当前大值 + 「较基线 +2.0 ↑」警示徽标（基于真实触发幅度，非自造阈值）。
   - **sparkline**：canvas 2d 折线，72 个点（1 分钟级），正常段灰蓝、异常段品牌蓝；**缺测时段橙色底纹且线条断开**（原型用占位序列挖空 12 点演示）；注「缺测时段不连线」。
   - **官方快照独立分区**：浅蓝卡，水质类别 Ⅱ 大字（Ⅰ/Ⅱ 青、Ⅲ 橙）、9 指标中 6 项网格（溶解氧/pH/氨氮/高锰酸盐/总磷/浊度），
     底部「数据已陈旧 · 发布于 42 小时前（STALE）」+ [官方公开]；明确**不进入趋势连续线**。
   - 卡脚关联事件红徽（TW-002）、开放盲区计数。

交互态：卡展开/收起、指标 tab 切换重绘 sparkline、点事件号跳事件详情、点候选区进入断面详情。

### 2.3 任务详情 `s-detail`（截图 `shot-s-detail.png`，演示退回态）

1. Hero：红色「需重提 · IN_PROGRESS」徽标（明确标注底层状态仍是 IN_PROGRESS，不存在 REJECTED 态）+ 高优白徽；任务名；chips（河段/动作/截止/taskId）。
2. **退回横幅**上浮压在 Hero 下沿：左红条、标题「复核未通过，请补充后重新提交（任务仍为进行中）」、
   引用复核意见原文、复核人 + 时间（真实 `latestReview.comment/reviewer/reviewedAt`）。
3. 异常背景卡：关联事件蓝链接、触发指标（水位 ↑ +2.0m）、派发理由。
4. 我的提交记录：版本卡 v1，顶部「第 1 次提交 + 需重提」；结论/时间/照片数/复测项；观察笔记；
   红色 review-box 展示退回意见（通过态为青绿 box，M0 未重复出图，组件两态已定义）。
5. 现场照片缩略图行。
6. 固定底部单按钮「补充记录并重新提交」→ record。
   其他状态按钮矩阵（已实现，M0 不重复出图）：PENDING 接收 / ACCEPTED 开始 / IN_PROGRESS 填写记录 /
   SUBMITTED 禁用「等待 PC 复核」/ APPROVED 完成卡 / CANCELLED 取消卡。

### 2.4 现场采集 `s-record`（截图 `shot-s-record.png`）

1. Hero：任务名 +「第 2 次提交 · v2」chip + 需重提徽标；下方**虚线蓝 chips 为本任务要求测量项**
   （「本任务要求测量：水位、浊度」——必填项由任务要求派生，非全局硬编码）。
2. 退回意见横幅（简短引用）。
3. **人工复测卡**：
   - 每行：青色图标 + 名称（「任务要求」徽标仅标在要求项上）+ 校验说明 + 输入（水位/浊度数字输入，水流 0–3 步进器）；
     行尾单位；头部统一挂 [人工测量 · 非传感器] 来源标。
   - 校验文案明确区分两类：**格式校验**（是数字、>0、步进为整数）与**参考区间提示**（超出仅软提示，不拦截，不伪装成业务合法范围）。
   - 「有要求项无法测量？」折叠区：原因胶囊（安全无法靠近/设备故障/点位被淹没/天气能见度/其他），
     **要求项要么填值、要么选原因，不允许静默留空**；非要求项不填无需原因。
4. 观察记录卡：textarea（预填占位文本演示）+「按住说话」语音按钮（现有同声传译插件/手动降级链路保留）；
   底部来源标记（语音转写/手动输入）+ 字数。
5. 照片卡：五态缩略图——已上传/上传中(62%)/失败(整格可点重试)/＋添加；失败重试为**单张**，不牵连其他张；
   标题处写本任务照片要求（「要求水尺近景 ≥1」同样来自任务要求）。
6. 现场结论：三选一 radio（NORMAL/ABNORMAL/UNCERTAIN），ABNORMAL 下注明「是否再评估由后端规则决定」。
7. **提交前检查清单**：要求项完成情况、记录、结论、失败照片（未过项橙色 ! 并禁用提交按钮，按钮实时显示原因）。
8. 固定底部主按钮（渐变），禁用态变灰。

## 3. 交互/视觉状态清单（M1 实现时逐态验收）

- 按钮：normal / :active（opacity .85）/ disabled（灰底 #EDF1F6）/ loading（微信 loading + 防重点）。
- 卡片：默认 / 按压（投影加深、微缩放 0.99）/ 展开（蓝描边+蓝投影）。
- 徽标六色 + 数据来源三标（模拟/官方/人工）；时间统一「相对时间 + 详情页绝对时间」。
- 断网/超时/401：401 在演示模式下不冒充登录成功（M5 鉴权双模式处理，本阶段只呈现错误态样式）。
- 横屏不做适配（竖屏手持场景）；最小宽度 320px（iPhone SE）下指标三列不换行、横滑卡可用。

## 4. 与业务约束的对应

| 约束 | M0 体现 |
|---|---|
| 不发明 REJECTED 任务态 | 详情/工作台均显式「IN_PROGRESS + 需重提」双标 |
| 必填项不全局硬编码 | 要求项来自任务 chips；未测必须选原因；格式校验与业务范围分离 |
| 链路离线 ≠ 数据消失 | 橙色链路胶囊 + 最后有效观测值/时间同卡并列 + 显式解释文案 |
| 官方快照不当实时数据 | 独立浅蓝分区、STALE 年龄、不进 sparkline、来源标「官方公开」 |
| 全部数据带来源/时间/新鲜度 | 指标卡时间戳、来源标；相对时间 + 快照发布时间 |
| 筛选/WS/FSM/版本机制不回归 | 原型沿用同一交互模型；M1 实现时 taskFilters 纯函数与 12 个单测原样保留 |
| 无新增外部依赖 | 纯 HTML/CSS/canvas/SVG；小程序落地同样零 npm 新增 |
